## Method

### Keep this in mind

A trajectory is made up of actions, states and rewards. The return of a trajectory is the summation of all the trajectory points. the goal in RL is to have a policy that maximizes the expected return.&#x20;

But I want to think about this in terms of inputs and outputs, i.e what are we optimizing for and how is transformer helping. Here's how I understand the algorithm:&#x20;

#### TD Learning

Let's establish some terminology first:&#x20;

1. s is state drawn from a set of states S
2. a is action drawn from a set of actions A, actions are taken when given a state.&#x20;
3. a reward is drawn based on the action taken, denoted as r.&#x20;
4. return is defined as the expected accumulation of rewards in an episode (start to end simulation of the environment).&#x20;
5. A value function gives the expected cumulative reward given the current state.&#x20;
6. A markov decision process assumes that any given state in an episode follows the markov property; in simple terms a markov state is provides enough information to the agent to make a decision. It's normal in RL to assume all states follow the markov property (that doesn't mean non-markov problems don't exist, the above assumption is only made for convinience).&#x20;

There are a lot of algorithms that are defined in RL to solve problems. The part that they focus on is estimating the value function, because a good value function can help us understand our policy. The ones that are of interest to us are monte carlo methods, dynamic programming and of course, TD learning (TD \= temporal difference).&#x20;

1. **Dynamic programming methods** apparently have this problem of knowing the entire enviorrnment in some way before estimating the value function? This point needs addressing.&#x20;
2. **Monte carlo** methods do RL by averaging sample returns across episodes. And apparently one of the main problems with monte carlo methods is that the return can only be calculated once we reach the end of the episode.&#x20;

TD learning combines Monte Carlo sampling with dynamic-programming-style bootstrapping. It is easiest to see the difference by comparing their value updates.

A constant-step-size Monte Carlo method updates the value estimate after the full return is known:

$V(S_t) \leftarrow V(S_t) + \alpha \left[G_t - V(S_t)\right]$

The simplest temporal-difference method, TD(0), updates after only one step:

$V(S_t) \leftarrow V(S_t) + \alpha \left[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\right]$

Here, $V(S_t)$ is the estimated value of state $S_t$, $\alpha$ is the step size, $G_t$ is the actual return following time $t$, $R_{t+1}$ is the next observed reward, and $\gamma$ discounts future rewards. Monte Carlo uses $G_t$ as its target and therefore waits until the episode ends. TD(0) instead uses the bootstrapped target $R_{t+1} + \gamma V(S_{t+1})$, so it can learn immediately at the next time step.

Now that we know the basics of TD learning, we can proceed to read the paper's results.&#x20;
